\section{Xây dựng Monitoring}

\subsection{Metrics Collection}

Metrics từ Cloud service và Edge Agent được nhận qua \cbs{giao thức/collector},
chuẩn hóa tên và lưu trong \cbs{time-series database}. Nhãn có cardinality cao
như command id không được gắn vào mọi metric; chúng phù hợp hơn với log hoặc
trace.

\subsection{Rule-based Detection}

Rule engine đánh giá cửa sổ metric theo chu kỳ. Rule gồm biểu thức, duration,
severity, cooldown và fingerprint template. Ví dụ: FPS thấp hơn ngưỡng trong
\cbs{thời gian} hoặc nhiệt độ vượt ngưỡng trong nhiều mẫu liên tiếp.

\subsection{Incident Creation}

Detection event được gửi đến Incident Service cùng metric snapshot và resource
reference. Fingerprint giúp cập nhật incident đang mở thay vì tạo bản ghi mới.
Khi metric phục hồi đủ lâu, hệ thống đánh dấu recovered nhưng vẫn yêu cầu policy
quyết định có tự động đóng incident hay không.

\subsection{Alert Processing}

Alert được định tuyến theo severity và resource label tới \cbs{kênh thông báo
thực tế}. Notification chứa incident id và liên kết Dashboard, tránh gửi toàn bộ
dữ liệu nhạy cảm. Retry và trạng thái delivery được lưu để đo alert delivery
latency ở Chương 6.
